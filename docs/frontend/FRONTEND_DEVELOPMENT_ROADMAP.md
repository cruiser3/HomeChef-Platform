# 前端开发流程路线图（FRONTEND_DEVELOPMENT_ROADMAP）

> **版本**：V1.0（2026-11-13）
> **定位**：本文件是后续整个前端开发工作的**统一实施依据**。每次开发前必须先读本路线图 → 相关需求 → 接口文档，再实施当前阶段。
> **事实口径**：所有"后端能力"以当前实际源码为准；接口细节以 `docs/backend/API_FRONTEND_CONTRACT.md` 为准；业务边界以 `docs/requirements/REQUIREMENT_CONTEXT.md` 为准。标记「未实现」的能力**不得**当作已具备能力排入开发。
> **执行纪律**：每次只推进一个明确阶段，完成后先测试、审查、汇报，经用户确认后再进入下一阶段；不擅自扩大需求、不重构后端、不修改数据库。

1. 本路线图规定前端阶段划分、每阶段的任务/接口/验收/测试/风险，以及进度与文档管理方式。
2. 开始任何阶段前，先读：本路线图 → `API_FRONTEND_CONTRACT.md` → `REQUIREMENT_CONTEXT.md` → 相关后端源码。

4. 每完成一个阶段：更新进度、记录真实测试结果（区分「计划 / 源码推导预期 / 实测」）、经用户确认后再进入下一阶段。

- **卡片式布局**、适当圆角与留白、清晰信息层级。

  - `--bg: #FAF6EF`（奶油白）、`--card: #FFFFFF`、`--primary: #6B9E7C`（浅绿）、`--primary-dark: #558767`
  - `--text: #33413A`、`--text-secondary: #93A19A`、`--accent: #E8B04B`（暖黄）、`--danger: #D05A4E`
  - `--radius: 14px`、柔和阴影 `0 2px 12px rgba(0,0,0,0.04)`

## 5. 后端接口约束总表（必须遵守，防误用）

| # | 约束 | 前端落地要求 |
|---|---|---|
| 1 | 系统角色（`User.Role`）≠ 家庭角色（`FamilyMember.FamilyRole`：ADMIN/MEMBER） | 家庭权限判断只用 `FamilyResponse.currentUserRole` 或菜品 `createdBy`，**不要用** `AuthResponse.role` |
| 2 | 家庭业务接口必须带 `X-Family-Id` | 统一请求拦截器自动附加当前家庭 ID；缺失会 400 |
| 3 | JWT 通过 `Authorization: Bearer <token>` 传递 | 统一请求拦截器自动附加 |
| 4 | 购物车为个人独立（用户+家庭隔离） | 切换家庭后重新拉取；不跨成员展示 |
| 5 | 订单家庭共享 | 任何成员可看/协作；取消仅下单人 |
| 6 | 订单金额以服务端返回为准 | 只展示 `totalAmount`/`subtotal`/`unitPrice`，**不自行计算最终金额** |
| 7 | 菜品/订单遵循家庭隔离与权限校验 | 处理 403；不信赖前端隐藏按钮 |
| 8 | 旧外卖写接口冻结；旧 `/api/orders` 非家庭订单 | **不接入** `/api/restaurants`、`/api/menu-items`、`/api/orders`、`/api/chat` |
| 9 | 采购清单已支持查看/新增/编辑/标记已购/删除 | 前端提供编辑/标记已购/删除按钮（后端校验成员资格） |
| 10 | 邀请码加入、移除成员、改角色均已实现 | 邀请码可查看/重置/凭码加入；管理员可移除成员/改角色（含最后管理员保护、不能移除自己） |
| 11 | 无图片上传服务 | 图片以 URL 字符串录入/展示，**不假设有上传接口** |
| 12 | AI 菜谱导入/小红书解析/AI 饮食建议为后续扩展 | 不纳入第一版 |

补充约束（源码审查所得）：
- **备菜状态机**（`CookStatus`）：`PENDING→COOKING/BLOCKED`；`COOKING→READY/BLOCKED`；`READY→SERVED/BLOCKED`；`BLOCKED→PENDING/COOKING/READY`；`SERVED` 终态。前端只提供当前状态允许的下一状态；`BLOCKED` 必填 `blockedReason`。
- **订单状态**：`CREATED→PREPARING`（开始备菜）；`CANCELLED`（取消）。取消条件：下单人本人 + 状态 `CREATED` + 全部菜品 `PENDING`。
- **加购/下单限制**：下架菜品不可加购/改量/下单；购物车数量 1~99；购物车为空不可下单。
- **未认证**：`SecurityConfig` 当前返回 401（`BACKEND_PROGRESS.md` G-01 有历史 403 记录），前端对未登录兼容 401/403，以实测为准。

## 6. 前端工程质量规范

1. **API 统一封装**：单一 axios 实例 + 模块 API 方法，页面不重复写请求逻辑。
2. **状态管理**：Pinia 管理 `token`、当前家庭 `familyId`、用户信息；持久化到 `localStorage`。
3. **统一错误处理**：响应拦截器处理 400/401/403/404/409/500；`message` 提示、`fieldErrors` 用于表单字段级错误。
4. **表单校验**：前端先校验（必填、格式、范围），但**后端校验为最终依据**。
5. **加载/空/失败/防重复**：列表有 loading、空态、失败重试；提交类按钮防重复点击（loading 禁用）。
6. **状态一致性**：订单/备菜状态文案与取值严格用后端枚举，不自造状态。
7. **组件复用**：抽取卡片、列表项、状态标签、空态、提交栏等通用组件。
8. **权限与边界**：重要操作考虑权限、边界与异常；隐藏按钮不是权限控制，后端仍强制校验。

### 阶段 5：厨房——订单与备菜协作模块

- **阶段目标**：订单列表、详情、取消、开始备菜、备菜状态更新、负责人分配、开饭标记。
- **开发任务**：订单列表（当前/历史、状态标签）；详情（菜品明细、状态）；开始备菜/开饭/取消（按状态与权限显示）；单菜备菜状态流转；负责人分配。
