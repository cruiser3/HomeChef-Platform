# 前端设计初稿（FRONTEND_DESIGN）

> **文档版本**：V0.2（2026-11-13）
> **状态**：技术选型与主导航结构已确定（见第 2、3、4 节）；阶段 1 已实现基础布局与导航框架，业务页面**详细设计尚未编写**，待阶段 2~7 逐模块展开。
> **依据**：接口能力以 `docs/backend/API_FRONTEND_CONTRACT.md` 为准（已按源码核实）；业务边界以 `docs/requirements/REQUIREMENT_CONTEXT.md` 为准；开发阶段划分以 `docs/frontend/FRONTEND_DEVELOPMENT_ROADMAP.md` 为准。
> **风格参考**：用户提供的微信小程序界面截图（菜品库首页 / 创建菜品 / 安排下单）。

---

## 1. 设计目标

- 面向家庭、情侣、合租等熟人小群体，**手机使用为主**，桌面端可用。
- 简洁、美观、实用、方便；优先跑通"登录 → 选家庭 → 看菜 → 加购 → 下单 → 看订单 → 备菜"主闭环。
- 不实现后端尚未提供的能力（邀请码、资料偏好、评论等，见交接文档第 9 节）。

---

## 2. 技术选型（已确定）

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3（`<script setup>`）+ Vite | 上手快、中文文档友好、生态成熟；Vite 兼容 Node LTS |
| UI 组件库 | Vant | 移动端组件齐全（Tabbar/按钮/列表/表单/弹窗/Picker 等），契合「手机为主」场景；桌面端通过响应式增强适配 |
| HTTP | axios | 封装请求/响应拦截器 |
| 路由 | Vue Router 4 | SPA 页面导航（阶段 1 引入） |
| 状态管理 | Pinia | 存登录态 `token`、当前家庭 `familyId`（阶段 2 引入） |

> 说明：Vue 3 + Vite + Vant + Axios 已确定为当前前端技术方案；Vue Router、Pinia 为基础技术，按 `FRONTEND_DEVELOPMENT_ROADMAP.md` 阶段 1/2 渐进引入。
> 备选 React + antd-mobile 未采用：Vant 移动端组件更完整、中文文档更友好，与「温馨生活风」目标更贴合（评估过程见 `DECISION_LOG.md` D-018 状态更新）。

### 2.1 两个关键拦截器（"方便"的核心）
- **请求拦截器**：自动附加 `Authorization: Bearer <token>` 与 `X-Family-Id: <当前家庭>`，页面无需重复书写。
- **响应拦截器**：统一处理 401（跳登录）、403（无权限提示）、400/404/409（展示 `message`）、表单错误（`fieldErrors`）。

---

## 3. 移动端优先 + 桌面端响应式增强（设计原则，已确定）

- **移动优先**：以移动端竖屏为基准设计，大字号、大按钮、底部 Tab，触控友好。
- **桌面端响应式增强**：通过 CSS 媒体查询（断点约 768px）自适应宽屏——主容器限宽居中、顶部导航、菜品多列卡片网格；内容相同、排版不同，不为手机/桌面各写一套。
- 手机访问方式：与电脑同一局域网下，浏览器访问 `http://<电脑IP>:5173`（Vite dev server，已配置 `host: 0.0.0.0`）。

---

## 4. 主导航结构（已确定，五个独立模块）

第一版保留 **5 个主导航模块**（用户已确认，见 `DECISION_LOG.md` D-020）：

| # | 主导航模块 | 对应后端能力 |
|---|---|---|
| 1 | 小家（菜品库） | `Dish`：菜品列表/分类/搜索/详情/创建/编辑/上下架 |
| 2 | 厨房（订单与备菜协作） | `FamilyOrder`：下单/订单/备菜状态/负责人/开饭 |
| 3 | 购物车 | `CartItem`：个人独立购物车（用户 + 家庭隔离） |
| 4 | 采购清单 | `FamilyShoppingItem`：查看 + 新增缺少食材 |
| 5 | 家庭 | `Family`：家庭信息/成员/切换 |

- 电脑端与手机端分别采用适合各自屏幕的导航布局（见第 3 节）：手机端底部 Tab，桌面端顶部导航。
- 各业务页面的**详细设计（布局、交互、字段）待阶段 1~7 逐模块展开**，不在本设计文档提前编写。
- 二级页（登录/注册、菜品详情、下单等）随对应阶段规划，此处不展开。

> 占位（后端未实现，先不做）：邀请码加入、个人资料/饮食偏好、订单评论。

## 5. 设计风格参考（来自微信小程序截图）

以下为从参考截图提炼的、可复用到本项目的布局与视觉要点：

### 5.1 菜品库首页（参考"菜单"页）
- 顶部：日期 + 大标题（如"今天吃什么？"），下方"菜单 / 安排"分段切换。
- 搜索框：圆角、占位提示"搜菜品、套餐"。
- 左侧纵向分类导航（荤菜/素菜/汤羹/主食…），右侧菜品列表。
- 菜品卡片：缩略图 + 菜名 + 标签（分类/自建）+ 耗时，右下角圆形"+"加购。
- 右上角"+"用于新建菜品；底部主 Tab。
- **视觉**：浅色背景、圆角卡片、大留白、标签用浅底色小胶囊。

### 5.2 创建 / 编辑菜品（参考"创建菜品"页）
- 顶部返回 + 居中标题；菜品图占位（"拍照/相册"）。
- 表单项：菜名（必填*）、分类（必填*）、耗时/分钟。
- "食材与做法"作为可展开的子入口。
- 底部深色大按钮"保存菜品"。
- **视觉**：极简表单、右侧值/箭头、分组留白、单一主按钮。

### 5.3 提交订单 / 安排（参考"安排"页）
- 用餐日期、餐次选择（对应 `mealPeriod`）。
- 已选菜品列表（可逐条 ×删除，对应购物车）。
- "给大厨的备注"（对应 `remark`）。
- 底部深色大按钮"确认安排"。

### 5.4 统一视觉规范（建议）
- 一个主色调 + 灰白背景；卡片式布局、圆角、充足留白。
- 移动端"大字 + 大按钮 + 底部 Tab"，触控友好。
- 不堆砌颜色与图标。

## 6. 核心交互闭环（第一阶段验收目标）

1. 注册 / 登录 → 拿到 `token`。
2. 创建 / 选择家庭 → 记录当前 `familyId`。
3. 浏览菜品（分类/搜索）→ 查看详情。
4. 加入购物车 → 修改数量 → 提交订单（选餐次/备注）。
5. 查看订单 → 开始备菜 → 逐菜改备菜状态 / 指定负责人 → 开饭。
6. 缺食材时：标记 `BLOCKED` 并到采购清单登记。
